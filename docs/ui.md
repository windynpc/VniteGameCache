# Vnite UI Requirements

## 右键菜单

- 缓存并启动
- 直接从 NAS 启动
- 仅同步存档
- 刷新文件索引
- 验证缓存
- 清除本地缓存
- 固定或取消固定缓存
- 打开 NAS 目录
- 打开 SSD 缓存目录
- 查看任务日志

## 状态显示

- 未缓存
- 已缓存
- 缓存过期
- 正在复制
- 正在验证
- 正在运行
- 等待存档同步
- NAS 离线
- 存档冲突
- 缓存损坏
- 固定缓存

## 游戏设置

- NAS 源路径
- SSD 缓存路径
- 启动程序
- 启动参数
- 工作目录
- 启动策略
- 缓存策略
- 校验策略
- 存档路径
- 排除规则
- 额外进程名

## UX 原则

- 正常用户只需点击一次“启动”
- 首次缓存明确显示进度
- 第二次启动不得再次显示长时间扫盘
- 错误信息必须可操作
- 删除缓存必须明确显示影响

## VGC 控制台

控制台是面向用户的本地修复和缓存管理入口，不再把内部调试按钮全部平铺在一个页面。

页面结构：

- 游戏管理：搜索、筛选、排序、精简游戏表格、右侧详情面板和常用操作。
- 缓存任务：显示复制进度、最近缓存活动、清理建议和清除缓存入口。
- 修复中心：接管诊断、一键修复、手动修复、过期记录扫描和重复游戏扫描。
- 操作记录：查看最近日志和启动详情。
- 设置与诊断：共享配置、自检报告、维护模式、日志目录和项目目录。

删除语义：

- 清除缓存：只处理本地缓存，默认移动到 Quarantine；不删除 NAS/G 盘源游戏、不删除 Vnite 元数据、不删除插件记录。
- 仅删除插件记录：只删除 VGC SQLite 记录和可确认归属的 VGC Wrapper 快捷方式；删除前自动备份数据库。
- 删除插件记录并清除接管属性（推荐）：删除 VGC 数据记录，并清空 Vnite 游戏属性中残留的 Wrapper、`.lnk`、`--game-id`、脚本和追踪字段。
- 一键清除接管属性：不删除 VGC 数据记录，只把 Vnite 游戏条目恢复到可重新检测状态。
- 清除后重新接管：先清除接管属性，再调用现有自动接管链路重新选择启动程序和生成 Wrapper。
- 扫描过期记录：只生成报告，不自动删除。
- 扫描重复游戏：只生成报告，不自动合并。

交互规则：

- 主表格默认只显示游戏名称、管理状态、接管状态、缓存状态、启动模式、问题、最近游玩和缓存大小。
- Game ID、Vnite ID、源目录、缓存目录、启动程序、快捷方式和候选启动程序显示在详情面板。
- 双击问题或默认列进入手动修复引导；双击缓存状态可打开缓存目录或触发手动缓存。
- `Delete` 键必须先弹出语义选择，不得直接删除。
- 游戏管理页必须固定显示 `清理 / 删除 ▼`，并在下拉菜单中明确区分 `清除缓存`、`删除插件记录`、`解除接管`、`永久忽略`、`取消忽略`、`完全重置当前游戏` 和 `从 Vnite 删除（高级危险操作）`。
- `删除插件记录` 是临时删除 VGC 接管记录，用于重新接管或重新生成；不得等同于 `永久忽略`。
- `永久忽略` 是长期跳过该游戏的管理意图，只有用户选择取消忽略后才恢复。
- `接管残留` 是 Vnite 游戏属性仍包含 VGC 启动字段，但 SQLite、PluginDB 或快捷方式链路不完整；控制台必须显示为待处理问题，而不是已接管。
